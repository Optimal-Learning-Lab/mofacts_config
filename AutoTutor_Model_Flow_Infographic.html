Runtime Architecture: LLM Interpretation + Deterministic State Machine

The LLM scores learner language and writes the tutor voice. The application validates envelopes, preserves durable evidence, chooses targets/moves, checks thresholds, and persists each turn.

Learner

Submit answer

Reject blank input. Reject new input if session already completed.

Semantic scorer

  • expectation coverage 0-1
  • misconception current/confidence/repaired
  • learner question + contribution type
  • answer quality
Router

State merge

Cost cap pre-check

Gate

End-state criteria

1Question branch

target=learner_question -> answer_question

Triggered by substantive learner question. Tutor answers only from authored lesson content and dialogue context, then keeps the session moving.

2Misconception branch

target=misconception -> correction

Only for substantive learner contributions. Selects highest-confidence unrepaired misconception at confidence >= 0.65.

3Completion branch

target=completion

All required expectations are covered. Move is summary, unless final integrated answer is enabled.

4Expectation branch

target=expectation

Select uncovered required expectation. A focused expectation can persist up to 6 turns, especially for low-agency learner turns.

Active Dialogue Moves Are Embedded in the Branch Loops

Each learner response returns to scoring; the planner advances, routes away, or loops back.

Move

pump

Low answer quality on the first focus turn. Invites more explanation without giving content away.

Cycle 1

hint

Light cue from authored hints. Also favored for uncertainty, affect, meta, and off-task turns.

Cycle 2

prompt

Targeted question for missing elements, near-covered expectations, or repeated help/idk.

Cycle 3

assertion

States the missing idea and asks learner to restate or apply it.

Next turn

Score learner response

Post-assertion uptake can count as learner knowledge; repair answers are scored against repairCriteria.

Criterion

Covered?

If coverage >= 0.8, route onward. If not, loop back to expectation support.

Repeated idk or help_request escalates across turns: hint -> prompt -> assertion. The assertion itself is not learner knowledge; the learner's later restatement/application is.
Stage 1

hint

Light cue toward the contrast; do not fully state repair yet.

Stage 2

prompt

Ask learner to make the key contrast explicit; vary the wording.

Stage 3

assertion

State the correct distinction and ask learner to restate/apply repair.

Criterion

Repaired?

If repaired: current=false, confidence=0, repaired=true.

If still active, continue hint -> prompt -> assertion correction stages. If no active misconception remains, clear misconception focus and route to question, completion, or expectation support.

Completion and End-State Loop

Graduation is authored per unit. Mastery requires covered required expectations and active misconceptions within limits; non-mastery stops are explicit.

Optional move

final_answer_prompt

Ask for one final integrated learner answer when enabled.

Move

summary

Bottom-out synthesis from authored script.

Graduation

Mastery criteria

  • covered required >= authored threshold
  • active misconceptions <= authored threshold
Terminal

End reasons

mastery, max_turns, or cost_cap.

Logged

History action

autotutor-complete, ended-max_turns, or ended-cost_cap.

Non-terminal

in_progress

If no terminal gate fires, the turn is written and the next learner answer re-enters the main loop.

Move catalog

Active planner moves

pump: invite elaboration. hint: light cue. prompt: targeted missing element. assertion: state idea and ask uptake. correction: misconception repair. answer_question: answer bounded content question. final_answer_prompt: optional synthesis attempt. summary: completion synthesis.

Reserved contract values

Not emitted by current planner

The move type union includes feedback and question_prompt, but current planner selection paths do not emit them.
